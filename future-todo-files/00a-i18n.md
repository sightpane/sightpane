# feat(dashboard,backend): multi-language support — dashboard strings, API error codes, language selection

> **Status: done (2026-09-09).** All acceptance criteria are met; for the details see
> `frontend/README.md` "Language", `backend/README.md` "Error body and codes" and `CLAUDE.md`
> "Localization". This file stays as a record.

## Problem

The dashboard is single-language: 194 Turkish strings under `frontend/lib` are embedded directly
in widgets (densest: `session_detail_page.dart` 26 lines, `overview_page.dart` 25,
`settings_page.dart` 20, `auth_pages.dart` 20, `projects_page.dart` 18). Date/number formats are
hard-wired to `tr` (`core/format.dart:5-8`, `main.dart:20`), `ShadcnApp.router` is locked with
`locale: Locale('tr')` (`app/app.dart:22`), `supportedLocales` lists `en` but picking `en`
changes no text at all. The backend's error messages are free-form English (21 `writeErr` calls
in the API handlers: `"login required"`, `"owner role required"`, `"no user with that
email; they must register first"` …) and the dashboard translates them **by looking at the
message text**: `core/auth.dart:41` `describeError` tells "wrong password" from "invalid
session" on a 401 via `e.message.contains('password')`; if the backend message changes, the
dashboard shows the wrong sentence. A team member who does not read Turkish cannot use the
dashboard.

## Why it matters

When a project outside the Casino CRM team arrives at the dashboard (or open-source users on
GitHub), the UI is unreadable. The backend-message-to-dashboard translation link is fragile:
once 02 (alert e-mail, Slack) and 10 (organizations) land, these strings will also go out to
e-mail/Slack; without a per-user language setting those end up single-language too. Since 0b
(Postgres) and the issues after it will touch the `users` table anyway, adding the `locale`
column now is cheap.

  `backend/internal/store/auth.go` and `backend/internal/store/store.go` also

**Contract / data**
- Error body: `{"error": "<English text>"}` → `{"error": …, "code": "<area.reason>"}`
  (e.g. `auth.login_required`, `auth.invalid_token`, `auth.invalid_credentials`,
  `auth.email_taken`, `auth.password_too_short`, `project.not_found`,
  `project.owner_required`, `member.unknown_email`, `member.owner_self_remove`,
  `envelope.key_required`, `envelope.unknown_key`, `envelope.too_large`, `bad_json`,
  `not_found`). The `error` text stays English (for curl/SDK users).
- `users.locale TEXT NOT NULL DEFAULT ''` + `GET/PATCH /api/v1/auth/me` (`{locale}`) — for the
  e-mail/Slack strings in 02; the dashboard also reads it from there on first load.
- Dashboard language source order: the `?lang=` query parameter → SharedPreferences `hog_locale`
  (`core/api.dart:309`, next to `TokenStore`) → `users.locale` → the browser
  (`PlatformDispatcher.instance.locale`) → `tr`.

## Fix shape

1. **Dashboard — gen-l10n.** `frontend/l10n.yaml` (`arb-dir: lib/l10n`, `template-arb-file:
   app_tr.arb`, `output-localization-file: app_localizations.dart`), `generate: true` in
   `pubspec.yaml`, `lib/l10n/app_tr.arb` (the source; today's strings) and `app_en.arb`.
   Keys are screen+meaning (`sessionsFetchFailed`, `settingsRotateKey`), placeholders are ICU
   (`{count} kare`, `{n} dk önce` with plural rules). Moving the 194 strings turns
   `const Text('…')` into `Text(l10n.x)`; `const` goes away — in `AppShell` the `NavEntry` list
   moves into `build`. `Fmt` takes a `locale` parameter (`Fmt.of(context)` or
   `Localizations.localeOf`); `percent()` via `NumberFormat.percentPattern(locale)`.
   `describeError` → `describeError(AppLocalizations l10n, Object e)`: a switch over
   `ApiException.code`; with no `code` (an older backend) it falls back to the status code.
2. **Language selection.** `localeProvider` (a Riverpod `Notifier<Locale>`; SharedPreferences
   `hog_locale`), `ShadcnApp.router(locale: ref.watch(localeProvider))`,
   `supportedLocales: [tr, en]`. A language switch in the top bar (`app_shell.dart`) and on the
   login page (`Select(adaptiveOverlay: false)` with two options, or a `Toggle`). `?lang=en`
   writes it on first load. After login, if `users.locale` is set it is applied; when it
   changes, `PATCH /auth/me`.
3. **Backend — codes.** `writeErr(w, code, key, msg)`, or `apiError{status, code,
   msg}` constants: the 21 call sites + the `code`s for the
   `ErrEmailTaken`/`minPassword` errors (this shipped as the `Code*` constants and the `Error`
   type in `backend/internal/apierr/apierr.go`). The `users.locale` column: the `migrate` CREATE
   **and** the ALTER list (`backend/internal/store/store.go`); the `User` struct
   (`backend/internal/store/auth.go`) + `me`/`PATCH me`
   (`backend/internal/server/auth_handler.go`). The `backend/main.go` log
   in English; `ui/index.html` bilingual, or English + `lang="en"`.
4. **Tests.** `pumpApp` passes the delegates and `locale: const Locale('tr')`, so the existing
   Turkish finders keep working; a "language switch" test finds `find.text('Sign in')` with
   `en`. Backend: `TestAuth` pins the `code` fields, `TestUsersProjects…` pins
   `project.owner_required` / `project.not_found`.

The hard part: `const` defaults such as `emptyText = 'Kayıt yok.'` have no context; the default
has to become `null` and be filled in from `l10n` inside `build`. Turkish uppercasing (`i` →
`İ`): the ARB strings are written out directly, `toUpperCase()` is not used. Do not change the
backend message text — during the transition `describeError` should work both through `code` and
through the old `contains('password')` path; one release later the `contains` is removed.

Rejected: translations loaded from JSON at runtime (no compile-time checking, a missing key
silently stays empty); having the backend translate text from `Accept-Language` (UI text is the
dashboard's job; the backend only supplies codes, and e-mail templates are handled separately in
02).
